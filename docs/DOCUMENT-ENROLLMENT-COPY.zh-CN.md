# 文档签名证书申请文案

归属：[CardKey #35](https://github.com/qianxueye/cardkey/issues/35)。本批文案已按 plain-language-iso-24495 审查；随本包界面生效，不代表安装、部署或实卡验收。

| 屏幕／键 | 原文 | 新文 | 原因与生效范围 |
| --- | --- | --- | --- |
| PIV／PKI · enrollment_document | 无 | 文档签名 | 新用途选项；选择后默认 9C。 |
| PIV／PKI · enrollment_documentScope | 无 | 使用所选槽位的现有密钥申请文档签名证书。不会生成或替换密钥。 | 说明已有密钥前提；仅文档签名用途显示。 |
| PIV／PKI · enrollment_document9a | 无 | 导入后将替换 9A 的现有证书，该文档签名证书不能用于 TLS 客户端认证。 | 保留替换后果及 TLS 限制；文档签名选择 9A 时显示，导入确认中再次显示。 |
| PIV／PKI · enrollment_scope | 令牌必须绑定此 CSR。此流程仅申请客户端认证证书；其他用途需另行申请。 | 令牌必须绑定此 CSR，并由 CA 管理员按所选用途授权。槽位仅决定本地导入位置。 | 两种用途共用；明确 CA 授权与本地槽位的界限。 |

沿用“槽位”“算法”、现有算法名称及槽位编号。沿用“CA 根证书”和替换证书确认文案。结果未知记录保留原申请的 CN 与 CA 地址；其他新申请不会覆盖它。客户端只在当前模型生命周期内阻止同一未知申请意图再次提交，不能据此宣称应用重启后仍保留阻止记录。
