# Android 管理工作台文案记录

对应任务：[CardKey #35](https://github.com/qianxueye/cardkey/issues/35)。

范围：Android Material 3 管理工作台、证书申请与 App 内 TLS 验证的布局。本批次按 Owner 已审阅方案及恢复后的直接应用授权实施；不增加证书用途、算法、槽位、账户或系统消费者的支持声明。CMS 文案由独立工作包负责。

| 屏幕／键 | 修改前 | 修改后 | 原因与范围 |
| --- | --- | --- | --- |
| 管理主界面／底部导航 | FIDO2、PIV、读卡器；证书申请与 TLS 表单位于 PIV 操作表单下方 | FIDO2、PIV、读卡器、证书申请 | 独立呈现证书任务，避免普通 PIV 操作后堆叠完整申请表单。切换页面不发送卡片指令。 |
| 设备区／`workspace_unread` | 无卡片状态说明 | 卡片状态尚未读取 | 读卡器发现或选择不表示卡片已认证。 |
| 设备区／`workspace_busy` | 操作结果区内进度条 | 操作执行中 | 设备区同时标明实际忙碌状态；进度条与取消保留。 |
| 设备区／`workspace_lastResult` | 仅操作结果区 | 最近操作结果见下方；不代表实时卡片状态 | 说明显示的是最近返回的结果，避免把保留结果当实时状态。 |
| 设备区／`workspace_inspection` | 仅结果区中的未知结果及恢复提示 | 结果待核实；请先读取卡片状态 | 设备区增加提示，原未知写入、更改后果和禁止重复提交的文案仍直接显示。 |
| 操作选择／`workspace_common` | 无分组的完整清单 | 常用任务 | 常用管理、凭据、证书与文件任务优先。原操作标题不变。 |
| 操作选择／`workspace_advanced` | 无分组的完整清单 | 高级与协议诊断 | 策略、重置、密钥生成及协议验证仍可达；不移除或放宽原确认。 |
| 结果／`workspace_details` | 技术字段全部展开，导出位于字段后方 | 技术详情 | 成功结果、验证边界、秘密查看确认、导出及保存状态在前；技术字段按需展开。失败、未知结果和后果不折叠。 |
| PIV 当前任务／`workspace_slotContext` | 无说明 | 槽位选择用于本次操作；证书状态需单独读取。 | 避免把选中槽位当成已经读取证书。 |
| FIDO2 当前任务／`workspace_credentialsUnread` | 空凭据列表无任务说明 | 凭据列表尚未读取；先读取 RP，再读取凭据。 | 明确既有真实库存流程的顺序；不创建演示凭据。 |
| 证书申请／`workspace_enrollmentFlow` | 原 CSR 与一次性令牌说明 | 生成 CSR → CA 签发 → 验证证书 → 导入并读回 | 增加流程顺序。原 TLS 用途、P-256／9A、令牌、显式导入、状态与未知签发说明保留。 |
| 证书申请／既有状态及未知回执 | 输入字段后方 | 申请标题、用途与固定槽位后方，输入之前 | 仅移动原文；显示每一步的实际结果及原未知回执归属。 |
| TLS 验证／既有结果 | 目标、根证书和 PIN 输入之后 | 验证标题及范围之后，身份与输入之前 | 仅移动原文；取消／超时可能已经提交认证等后果仍直接显示。 |

现有资源只有中文；本批次沿用该语言范围，不引入与中文含义不同的英文 UI。布局继续使用现有 Material 3 主题、系统颜色、导航、控件和输入法／系统安全区域处理。

软件检查与实体／系统验收分别记录。界面改动不表示生产部署、实体写卡、外部账户接受或系统 TLS／文档签名消费者已经合格。
