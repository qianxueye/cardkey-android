# Android CTAPHID transport

The Manager and Credential Provider can use a USB FIDO authenticator through CTAPHID. CTAP2 requests go directly to the HID CBOR command. U2F requests use the HID MSG command and standard extended APDU framing. A nonempty command has a seven-byte header and a two-byte expected-length field; the empty VERSION request is exactly seven bytes (`00 03 00 00 00 00 00`). These paths do not synthesize smart-card SELECT replies, relay pairing tickets, or carry PIV and GlobalPlatform commands. The existing NFC, CCID APDU and CCID T=1 paths remain available.

## Discovery and connection

USB discovery lists candidate HID interfaces from their interrupt endpoint shape without opening a device or transferring descriptors. A listed candidate is not yet a verified FIDO authenticator, even if Android has already granted permission. Connection runs on the operation worker and validates the report descriptor's FIDO usage page `F1D0`, usage `01`, and supported report layout before claim/INIT. Unsupported descriptors or interfaces fail before initialization.

The adapter supports one FIDO application collection with exactly one byte-wide Data/Variable/Absolute input stream (usage `F1D0:20`) and one output stream (usage `F1D0:21`). Both streams can be unnumbered, or both can use report IDs in `1…255`. Input and output IDs and payload sizes are independent; an output stream can inherit the input ID from descriptor global state. Mixed numbered/unnumbered streams, explicit ID zero, duplicate streams, extra collections, feature reports, padding, packed fields and PUSH/POP layouts remain outside this profile and fail before claim/INIT.

Each CTAPHID packet payload is 7–1,024 bytes. A numbered native report adds exactly one ID byte, making its native allocation 8–1,025 bytes; an unnumbered native report has no prefix. These are host profile bounds, not protocol maxima. The report descriptor remains limited to 4,096 bytes. Input and output native allocations use their respective descriptor lengths and IDs. Output prepends the ID once; input checks the exact native length and ID before exposing payload bytes. A foreign ID fails the operation without demultiplexing or retrying.

Report lengths come from the HID report descriptor. Interrupt endpoint packet sizes must be positive, but need not equal report lengths: a report can span multiple USB transactions. Each direction has wire capacity `min(65535, (size - 7) + 128 * (size - 5))`, using payload size without the report ID. The application retains its separate 7,609-byte message ceiling. A seven-byte report has no initial payload space and carries its payload in continuation reports.

The native adapter uses Android `UsbRequest` interrupt transfers. It does not use CCID bulk transfers for HID. INIT contains a fresh random nonce; the reply must match it and supply a valid channel ID and protocol capabilities. CTAP1 and CTAP2 availability follows those capabilities. Messages use the validated directional report lengths, their framing capacities, the application message ceiling, and the authenticator's advertised CTAP limits. Missing getInfo `maxMsgSize` retains the 1,024-byte default; a command must also fit the output transport capacity. Responses must match the channel, command, declared length and continuation sequence. INIT nonce matching and fragmented control messages use the same bounded reassembly. Well-formed reports for other channels and foreign INIT nonces are ignored within the original deadline. KEEPALIVE is intermediate; CANCEL has no separate acknowledgement.

PIV controls are unavailable on HID, and the protocol session rejects APDU commands before transmission. A local route key includes the device path, interface, wire and observed attachment generation. Detach invalidates old descriptors and permission callbacks, including when a later attachment reuses the path. A USB device path, interface, serial, VID/PID or AAGUID is not proof of card identity.

## Operation ownership and outcomes

One Manager or Provider operation holds the process-wide operation lease from connection through final channel closure. PIN agreement, token acquisition, inventory, assertions and Large Blob commands share that connection. No command phase reconnects or sends a new INIT. The Provider reserves its request claim before connection, so initialization cannot precede ownership of that request.

Cancellation retires native requests and buffers before the lease can be reused. Every native allocation, including the report ID and all payload bytes, is erased only after matching completion or cancellation reap/connection closure and request closure. A throwing queue remains possible native ownership. A response arriving after cancellation cannot release secret output or become a successful user result. Closing a USB connection releases its interface; it does not send a card power-off command. HID presence results do not start CCID removal probes or impose a smart-card removal requirement. Known terminal HID presence failures use the approved restart-and-touch/button hint. Unknown or fenced writes retain recovery guidance. The Manager displays the approved disconnect-all-power instruction only when the returned PIN power-cycle state is true; the Manager and Credential Provider use it for an actual temporary PIN-block status. The APDU/NFC card-removal sentence remains unchanged on those routes. KEEPALIVE updates the current operation’s waiting state, fenced to its channel and attachment generation, and the Manager and Credential Provider display the approved touch/button prompt only while that HID operation is waiting. Processing, terminal response, cancellation and disconnect clear that state. A waiting-state update is not proof of user presence or authorization.

An effectful request with a lost or malformed terminal response remains uncertain. Bridge CTAP status `7F`, U2F status `6F00`, and cancellation status `2D` after a possible effectful dispatch also preserve uncertainty. An earlier accepted write remains recorded. None of these outcomes causes automatic replay. A valid CTAPHID CHANNEL_BUSY rejection before any processing progress is a known busy failure and preserves previous effects. BUSY after KEEPALIVE, malformed errors and partial native-transfer failures remain uncertain; no retry is automatic.

After an unresolved HID write, routine inspection cannot clear the Manager's recovery fence, including inspection through a different route. An opaque USB route cannot establish that the same paired card is still present. A successful inspection is useful readback, but it does not resolve the earlier write by itself.

The controller profile under qualification uses a fixed channel ID of 1 and invalidates its paired protocol session on INIT. The app's lease and native interface ownership coordinate its own operations. They do not establish safe simultaneous use by another process, browser or management application.

## Verification boundary

Public tests use synthetic descriptors, report streams and cryptographic keys. They cover framing and reassembly, nonce and capability validation, cancellation and request retirement, session effects, both smart-card and direct CTAP routes, and signed Manager/Provider workflows. Numbered asymmetric fixtures cross the native interrupt adapter for real registration/assertion signature checks, encrypted PIN protocol 1 and 2 token flows, authenticated fragmented Large Blob writes/readback, U2F signatures, and cancellation. They retain the payload and message bounds, operation claims and leases, and uncertain-write protections. No private controller source, applet binary, pairing key, real credential or captured card secret is required by the build.

Phone USB permission behavior, actual interrupt transfers, controller presence/button behavior, disconnect/reconnect, physical power recovery, contention with other clients, Android provider selection, browser and relying-party acceptance require separate physical evidence. A software gate or a scripted signature check does not establish those results.
